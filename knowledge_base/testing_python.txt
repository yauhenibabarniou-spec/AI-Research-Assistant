# Тестирование Python приложений

Тестирование — это критически важный этап разработки программного обеспечения, который помогает обеспечить корректность работы кода, предотвратить регрессии и упростить поддержку. В экосистеме Python существует несколько зрелых фреймворков для тестирования.

## Уровни тестирования

### Модульные тесты (Unit Tests)
Тестирование отдельных компонентов системы в изоляции от остальной части. Обычно тестируют отдельные функции, методы или классы.

### Интеграционные тесты
Тестирование взаимодействия между несколькими компонентами системы. Например, взаимодействие между базой данных и бизнес-логикой.

### Системные тесты (E2E)
Тестирование всей системы как целого, имитируя действия реального пользователя.

### Приёмочные тесты
Проверка соответствия системы требованиям заказчика.

## Фреймворк pytest

pytest — самый популярный фреймворк для тестирования в Python. Он обеспечивает простой синтаксис и мощные возможности.

### Установка

```bash
pip install pytest pytest-cov
```

### Базовый пример теста

```python
# test_calculator.py
def add(a, b):
    return a + b

def test_add():
    assert add(2, 3) == 5
    assert add(-1, 1) == 0
    assert add(0, 0) == 0
```

### Запуск тестов

```bash
pytest                    # Запустить все тесты
pytest -v                 # Подробный вывод
pytest -k "test_add"      # Запустить тесты с именем содержащим test_add
pytest --cov=myapp        # Запустить с измерением покрытия
pytest -x                 # Остановиться на первой ошибке
```

## Fixtures в pytest

Fixtures — это функции, которые предоставляют тестовые данные или настраивают окружение для тестов.

### Базовый fixture

```python
import pytest

@pytest.fixture
def sample_data():
    return {"name": "test", "value": 42}

def test_sample_data(sample_data):
    assert sample_data["name"] == "test"
    assert sample_data["value"] == 42
```

### Scope fixtures

```python
@pytest.fixture(scope="session")
def database_connection():
    conn = create_connection()
    yield conn
    conn.close()

@pytest.fixture(scope="module")
def api_client():
    client = APIClient()
    yield client
    client.cleanup()
```

### Fixture с параметризацией

```python
@pytest.fixture(params=["sqlite", "postgres", "mysql"])
def db_connection(request):
    db_type = request.param
    conn = create_connection(db_type)
    yield conn
    conn.close()

def test_query(db_connection):
    result = db_connection.query("SELECT 1")
    assert result == 1
```

## Параметризация тестов

### @pytest.mark.parametrize

```python
import pytest

@pytest.mark.parametrize("input,expected", [
    (2, 4),
    (3, 9),
    (4, 16),
    (-2, 4),
])
def test_square(input, expected):
    assert square(input) == expected
```

### Несколько параметров

```python
@pytest.mark.parametrize("a,b,expected", [
    (2, 3, 5),
    (-1, 1, 0),
    (0, 0, 0),
    (100, 200, 300),
])
def test_add(a, b, expected):
    assert add(a, b) == expected
```

## Маркеры

Маркеры позволяют помечать тесты и запускать выборочно.

### Стандартные маркеры

```python
import pytest

@pytest.mark.skip(reason="Не реализовано")
def test_future_feature():
    pass

@pytest.mark.skipif(sys.version_info < (3, 9), reason="Требуется Python 3.9+")
def test_new_feature():
    pass

@pytest.mark.xfail(reason="Известный баг")
def test_buggy_feature():
    assert buggy_function() == expected

@pytest.mark.slow
def test_slow_operation():
    time.sleep(10)
    assert True
```

### Кастомные маркеры

```python
# pytest.ini
[pytest]
markers =
    slow: marks tests as slow
    integration: marks tests as integration tests
    unit: marks tests as unit tests

# test_example.py
@pytest.mark.integration
def test_database_operations():
    # Интеграционный тест
    pass
```

## Мокирование (Mocking)

Мокирование позволяет заменить реальные зависимости на тестовые двойники.

### unittest.mock

```python
from unittest.mock import Mock, patch, MagicMock

def test_api_call():
    mock_response = Mock()
    mock_response.status_code = 200
    mock_response.json.return_value = {"id": 1, "name": "Test"}
    
    with patch('requests.get', return_value=mock_response):
        result = fetch_user(1)
        assert result["name"] == "Test"
```

### pytest-mock

```python
def test_with_pytest_mock(mocker):
    mock_db = mocker.patch('myapp.database.get_connection')
    mock_conn = Mock()
    mock_db.return_value = mock_conn
    
    result = my_function()
    mock_conn.execute.assert_called_once()
```

### Side effects

```python
from unittest.mock import Mock, side_effect

def failing_mock():
    raise ConnectionError("Network error")

mock_func = Mock(side_effect=failing_mock)

def test_network_failure():
    with pytest.raises(ConnectionError):
        mock_func()
```

## Тестирование исключений

### pytest.raises

```python
def test_division_by_zero():
    with pytest.raises(ZeroDivisionError):
        divide(10, 0)

def test_custom_exception():
    with pytest.raises(ValueError, match="Invalid value"):
        validate_input(-1)
```

### Проверка информации об исключении

```python
def test_exception_info():
    with pytest.raises(ValueError) as exc_info:
        validate_input(-1)
    
    assert "Invalid value" in str(exc_info.value)
    assert exc_info.type == ValueError
```

## Лучшие практики тестирования

1. **Пишите тесты до кода (TDD)** или сразу после написания кода
2. **Один тест — одна проверка** — каждый тест проверяет одну вещь
3. **Используйте описательные имена** — `test_user_creation_with_valid_data`
4. **Изолируйте тесты** — тесты не должны зависеть друг от друга
5. **Используйте fixtures** — переиспользуйте общий код настройки
6. **Тестируйте граничные случаи** — пустые значения, None, большие числа
7. **Тестируйте исключения** — не только happy path
8. **Поддерживайте покрытие** — стремитесь к 80-90% покрытию
9. **Автоматизируйте** — тесты должны запускаться в CI/CD
10. **Рефакторите тесты** — поддерживайте тестовый код в порядке

## Распространённые ошибки

1. **Тестирование реализации, а не поведения** — тесты ломаются при рефакторинге
2. **Слишком большие тесты** — тестируют слишком много вещей сразу
3. **Хрупкие тесты** — зависят от времени, случайных данных, порядка выполнения
4. **Недостаточная изоляция** — тесты влияют друг на друга
5. **Дублирование кода** — повторяющийся код настройки в каждом тесте
6. **Игнорирование медленных тестов** — медленные тесты откладываются и забываются
7. **Тестирование только happy path** — исключения и ошибки не покрыты
8. **Жёсткое кодирование** — хардкод значений вместо использования fixtures
9. **Отсутствие документации** — непонятно, что тестирует тест
10. **Слишком много assertion** — тест проверяет слишком много условий

## Заключение

Тестирование — это не дополнительная работа, а неотъемлемая часть разработки качественного программного обеспечения. Правильно написанные тесты:

- Уменьшают количество багов в production
- Упрощают рефакторинг кода
- Ускоряют разработку новых функций
- Улучшают архитектуру кода
- Служат документацией для кода

Начните с простых модульных тестов для критически важного кода и постепенно расширяйте покрытие. Используйте pytest как основной фреймворк — он простой, мощный и имеет огромную экосистему плагинов.

Для продолжения изучения тестирования в Python рекомендуется:
- Освоить pytest fixtures и параметризацию
- Изучить мокирование с unittest.mock
- Научиться писать интеграционные тесты
- Изучить property-based тестирование с Hypothesis
- Освоить нагрузочное тестирование с Locust
