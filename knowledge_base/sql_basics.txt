# Основы SQL и реляционных баз данных

SQL (Structured Query Language) — это стандартный язык для работы с реляционными базами данных. Он используется для создания, управления и запроса данных в системах управления базами данных (СУБД), таких как PostgreSQL, MySQL, SQLite и других.

## Что такое реляционная база данных

Реляционная база данных — это база данных, которая хранит данные в виде таблиц (отношений). Каждая таблица состоит из строк и столбцов. Столбцы имеют определённые типы данных, а строки представляют отдельные записи.

Основные концепции:
- **Таблица (relation)** — набор данных об объектах определённого типа
- **Строка (tuple/record)** — отдельный экземпляр данных
- **Столбец (attribute/field)** — определённый тип данных
- **Первичный ключ (primary key)** — уникальный идентификатор строки
- **Внешний ключ (foreign key)** — ссылка на первичный ключ другой таблицы

## Основные типы данных SQL

### Числовые типы
- `INTEGER` — целые числа
- `BIGINT` — большие целые числа
- `SMALLINT` — малые целые числа
- `DECIMAL(p,s)` — числа с фиксированной точкой
- `NUMERIC(p,s)` — синоним DECIMAL
- `FLOAT` — числа с плавающей точкой
- `REAL` — числа с плавающей точкой одинарной точности
- `DOUBLE PRECISION` — числа с плавающей точкой двойной точности

### Строковые типы
- `CHAR(n)` — строка фиксированной длины
- `VARCHAR(n)` — строка переменной длины
- `TEXT` — текст произвольной длины

### Дата и время
- `DATE` — дата (год, месяц, день)
- `TIME` — время
- `TIMESTAMP` — дата и время
- `INTERVAL` — интервал времени

### Другие типы
- `BOOLEAN` — логическое значение
- `BLOB` — бинарные данные
- `JSON` — данные в формате JSON
- `ARRAY` — массив значений
- `UUID` — уникальный идентификатор

## Операторы SQL

- `+` — сложение
- `-` — вычитание

- `/` — деление
- `%` — остаток от деления

- `IN` — входит в список

### Специальные операторы
- `DISTINCT` — уникальные значения

## Команда SELECT

SELECT — это основная команда для выборки данных из базы данных.

```sql
SELECT column1, column2, ...
FROM table_name
WHERE condition
GROUP BY column1, column2, ...
HAVING condition
ORDER BY column1, column2, ... ASC|DESC
LIMIT number;
```

### Основные предложения SELECT

**SELECT** — указывает, какие столбцы возвращать
**FROM** — указывает, из какой таблицы брать данные
**WHERE** — фильтрует строки по условию
**GROUP BY** — группирует строки по значению столбца
**HAVING** — фильтрует группы по условию
**ORDER BY** — сортирует результат
**LIMIT** — ограничивает количество возвращаемых строк
**OFFSET** — пропускает указанное количество строк

### Примеры SELECT

```sql
-- Выбор всех столбцов
SELECT * FROM users;

-- Выбор конкретных столбцов
SELECT name, email FROM users;

-- Фильтрация с WHERE
SELECT * FROM users WHERE age > 18;

-- Сортировка
SELECT * FROM users ORDER BY created_at DESC;

-- Ограничение количества
SELECT * FROM users LIMIT 10;
```

## Функции агрегирования

Агрегирующие функции выполняют вычисления над набором строк и возвращают одно значение.

### Основные агрегирующие функции

- `COUNT()` — подсчёт строк
- `SUM()` — сумма значений
- `AVG()` — среднее значение
- `MIN()` — минимальное значение
- `MAX()` — максимальное значение

### Использование GROUP BY

GROUP BY объединяет строки с одинаковыми значениями в группы.

```sql
SELECT department, COUNT(*) as employee_count, AVG(salary) as avg_salary
FROM employees
GROUP BY department
HAVING COUNT(*) > 5
ORDER BY avg_salary DESC;
```

## Соединения (JOIN)

JOIN позволяет объединять строки из двух или более таблиц на основе связанных между ними столбцов.

### Типы JOIN

**INNER JOIN** — возвращает строки, когда есть совпадение в обеих таблицах
**LEFT JOIN** — возвращает все строки из левой таблицы и совпадающие из правой
**RIGHT JOIN** — возвращает все строки из правой таблицы и совпадающие из левой
**FULL JOIN** — возвращает строки, когда есть совпадение в одной из таблиц
**CROSS JOIN** — декартово произведение таблиц
**SELF JOIN** — соединение таблицы с самой собой

### Синтаксис JOIN

```sql
SELECT orders.order_id, customers.customer_name
FROM orders
INNER JOIN customers ON orders.customer_id = customers.customer_id;
```

## Подзапросы

Подзапрос — это запрос внутри другого запроса. Он может использоваться в предложениях SELECT, FROM, WHERE и HAVING.

```sql
-- Подзапрос в WHERE
SELECT name FROM employees
WHERE salary > (SELECT AVG(salary) FROM employees);

-- Подзапрос в FROM
SELECT dept_name, avg_salary
FROM (SELECT department as dept_name, AVG(salary) as avg_salary
      FROM employees GROUP BY department) as dept_stats
WHERE avg_salary > 50000;

-- Подзапрос с EXISTS
SELECT name FROM customers c
WHERE EXISTS (SELECT 1 FROM orders o WHERE o.customer_id = c.id);
```

## Индексы

Индексы ускоряют выборку данных из базы данных, но замедляют операции вставки, обновления и удаления.

### Типы индексов

- **B-tree** — сбалансированное дерево поиска, наиболее распространённый тип
- **Hash** — хеш-индекс, эффективен для точных совпадений
- **GiST** — общий поисковый árbol, для сложных типов данных
- **GIN** — инвертированный индекс, для полнотекстового поиска
- **BRIN** — блоковый диапазонный индекс, для больших таблиц

### Создание индекса

```sql
CREATE INDEX idx_users_email ON users(email);
CREATE UNIQUE INDEX idx_users_username ON users(username);
CREATE INDEX idx_orders_date ON orders(order_date);
```

## Транзакции и блокировки

Транзакция — это логическая единица работы, которая должна быть выполнена полностью или не выполнена вовсе.

### Свойства транзакций (ACID)

- **Atomicity (Атомарность)** — транзакция выполняется целиком или не выполняется
- **Consistency (Согласованность)** — транзакция переводит базу из одного согласованного состояния в другое
- **Isolation (Изолированность)** — параллельные транзакции не мешают друг другу
- **Durability (Долговечность)** — результаты успешной транзакции сохраняются постоянно

### Уровни изоляции

- `READ UNCOMMITTED` — можно читать незафиксированные изменения
- `READ COMMITTED` — можно читать только фиксированные изменения
- `REPEATABLE READ` — гарантирует, что повторное чтение даст те же данные
- `SERIALIZABLE` — полная изоляция, как если бы транзакции выполнялись последовательно

## Нормализация баз данных

Нормализация — это процесс организации данных для минимизации избыточности и зависимостей.

### Нормальные формы

**1NF (Первая нормальная форма):**
- Атомарные значения в каждом столбце
- Нет повторяющихся групп
- Каждая таблица имеет первичный ключ

**2NF (Вторая нормальная форма):**
- Удовлетворяет 1NF
- Нет частичных зависимостей от первичного ключа

**3NF (Третья нормальная форма):**
- Удовлетворяет 2NF
- Нет транзитивных зависимостей

**BCNF (Бойс-Кодд нормальная форма):**
- Удовлетворяет 3NF
- Для каждого нетривиального функционального зависимого атрибута ключ является суперключом

## Практические советы по SQL

1. **Используйте осмысленные имена** для таблиц и столбцов
2. **Документируйте схему** базы данных
3. **Создавайте индексы** для часто используемых столбцов в WHERE и JOIN
4. **Избегайте SELECT *** — указывайте конкретные столбцы
5. **Используйте подготовленные выражения** для защиты от SQL-инъекций
6. **Нормализуйте структуру** до 3NF, денормализуйте для производительности
7. **Используйте транзакции** для операций, изменяющих несколько таблиц
8. **Регулярно делайте бэкапы** базы данных
9. **Мониторьте производительность** запросов
10. **Тестируйте запросы** на реальных объёмах данных

## Частые ошибки при работе с SQL

- **N+1 проблема** — выполнение N+1 запроса вместо одного JOIN
- **Неиспользование индексов** — приводит к полному сканированию таблиц
- **Избыточные JOIN** — соединение лишних таблиц
- **Некорректная группировка** — использование неагрегированных столбцов в SELECT при GROUP BY
- **NULL в сравнениях** — использование `= NULL` вместо `IS NULL`
- **Потеря данных при JOIN** — использование неверного типа JOIN
- **Изменение данных без WHERE** — массовое обновление без фильтра
- **Хранимые процедуры** без необходимости — усложняют поддержку
